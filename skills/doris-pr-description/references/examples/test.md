Title: [test](regression) Fix flaky test_routine_load_restart

### Background

A routine load job consumes a Kafka topic continuously. The FE schedules its tasks in rounds, and `SHOW ROUTINE LOAD` reports the job's state, such as `NEED_SCHEDULE` or `RUNNING`. `test_routine_load_restart`, a P0 suite, pauses and resumes a job and checks that it runs again.

### What problem does this PR solve?

Issue Number: None
Related PR: None
PR Type: Test

Problem Summary:

`test_routine_load_restart` fails intermittently in P0 because it checks the job state right after `RESUME ROUTINE LOAD`, before the scheduler has picked the job up. This PR waits for the state to settle instead of asserting it once.

### Details

- **Failure:** `expected RUNNING but was NEED_SCHEDULE`, in about 1 of 15 P0 runs over the past two weeks, for example in the P0 run of #58901.
- **Cause:** `RESUME` only moves the job to `NEED_SCHEDULE`; the scheduler sets `RUNNING` on its next round, which can come after the assertion.
- **Stability evidence:** 50 consecutive local runs passed; before the change, 4 of 50 failed.

### Testing

- `./run-regression-test.sh --run -d load_p0/routine_load -s test_routine_load_restart`, 50 times locally.

None

Title: [test](regression) Cover delete sign with sequence columns on merge-on-write tables

### Background

On a Unique Key table with a sequence column, a load keeps whichever version of a row has the higher sequence value, so rows that arrive out of order cannot overwrite newer ones. A delete is a row with the hidden delete sign set, and it follows the same rule. Merge-on-write tables apply the rule when data is loaded rather than when it is read.

### What problem does this PR solve?

Issue Number: None
Related PR: #58302 (fixed deletes applied out of sequence order)
PR Type: Test

Problem Summary:

#58302 fixed deletes being applied out of sequence order on merge-on-write tables with a sequence column, but added a single case. This PR adds the cases around it, so that P0 catches a regression in how deletes respect the sequence column.

### Details

- **Scenarios:** A delete with a higher, an equal, and a lower sequence value than the current row; a delete followed by a re-insert in the same load and in separate loads; a partial update after a delete. Each runs on tables with and without cluster keys.
- **What existing tests miss:** `test_mow_delete_sign` covers deletes without a sequence column, and `test_mow_seq_col` covers upserts but not deletes.
- **Fails when broken:** With the fix from #58302 reverted, 3 of the 7 cases fail.

### Testing

- `./run-regression-test.sh --run -d unique_with_mow_p0 -s test_mow_delete_sign_seq` on a local shared-nothing cluster; the `.out` file is generated by the framework.
